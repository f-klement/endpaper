**Those figures are generated and nothing here is recounted by hand.**
`coverageRegister.reporter.ts` renders that block from the tasks of the run in hand and
fails the run when this document disagrees with it, row by row and file by file. No date
stands beside the numbers, because a figure a run recomputes has nothing to be as of. No
node either: a count does not depend on which worker produced it, where a duration would.

**A row is a glob**, so several rows stand for a directory and every row is expanded
before it is compared. Counting rows as though each named one file is how this register
came to state 81 rows over 179 files where the run had 82 over 180.

**Every file this suite collects has a row of its own or falls under one.** A file that
falls under none is reported by name rather than absorbed into a count of the files nobody
described: such a count is satisfied by any file, so the next undescribed one lands by
editing a digit. The one exception is a file the publish gate strips, which this published
register may not name: its tests are counted apart, in the block's own sentence, exactly as
the backend register does. No file here is stripped today, so that sentence is
absent above rather than reading zero.

**The written and the generated halves move with the instrument where the total does
not.** What decides which a test is lives in `coverageRegister.ts`, beside the figure it
produces, so quote it beside either half or quote neither. It is a walk over the parsed
source rather than a pattern over the text: the pattern it replaced counted a call written
inside a string literal, which is why one file published a written out figure two too high. An earlier
tree reported a total that moved by 4 across two runs with `tests/` byte identical between
them, and that difference was never reconciled: treat a small movement as a question
rather than as a regression.

## How these tests are written

They drive the **real generated hooks and the real mutator**, and stub only `fetch`. That
keeps them honest about query keys, cache invalidation and request shapes, all of which a
mocked API module would hide.

`mockApi()` in `utils.tsx` registers per-route handlers and records every request, so a
test can assert on the exact body sent:

```ts
api.on("/api/books/scan", { body: makeBook({ id: 12 }) });
// …
expect(api.lastCall("/api/books/scan", "POST")?.body).toMatchObject({
  is_private: true,
});
```

Anything not explicitly stubbed rejects loudly rather than reaching the network.

Queries go through **roles and labels**, never CSS classes. Class names are styling and
change freely; the accessible name is the contract. Several `aria-label` and `aria-pressed`
attributes in the source exist to make that possible, and improve the app for screen
readers as a side effect.

## The parts that matter most

**The mutator**, because everything routes through it: it carries the token, ends a stale
session and shapes every error the pages render. Two defects it now pins: a 401 resolving
`undefined`, so callers rendered with missing data instead of failing, and a 401 from the login
route treated as an expired session, which cleared the stored credentials of somebody merely
mistyping a password.

**Pagination**: a second page is appended rather than replacing the first, and `hasMore` goes
false when the loaded rows account for the reported total.

**The view, per mode**: two defaults, two keys, neither mode's write visible to the other, and
the window before the mode is known, where a write is refused rather than filed under a guess.

**The catalogues**: key parity is a compile time property, so the suite spends its effort on
what the types cannot see, chiefly that every placeholder the English declares survives into the
German.

**The Google Books gate**: every entry point asserted absent when the feature is off.

**Destructive bulk actions**: that a delete asks first, and that "Select all" covers only the
books actually loaded.

## Deliberate gaps

- **`src/api/generated/`**, which is Orval's output; testing it would test Orval.
- **`src/main.tsx`**, three lines of bootstrap.
- **Real rendering.** happy-dom has no layout engine, so nothing here catches a visual defect.
- **The camera.** The decoder is mocked wholesale.
- **Service worker behaviour.** The precache and update cycle are not exercised.
- **German rendering**, beyond spot checks: the catalogues are checked structurally.

## Conventions

- One behaviour per test, named as a sentence.
- **Prefer stubbing the network over replacing a module.** `vi.mock` is banned and enforced;
  use a double in `tests/doubles/` with a `test.alias` entry.
- Fake timers only where a debounce demands them, and with `fireEvent` rather than
  `user-event`, which deadlocks against them.
- Pick the smallest render helper that works: `renderLocalised`, `renderWithProviders`,
  `renderHookWithProviders`. All three default to English, so an assertion never depends on
  the machine's browser language. **The first two take a `locale`, which is how the German
  arms are written**; the third hardcodes English and offers no way past it, so a hook whose
  text is translated cannot be tested in German through it.
